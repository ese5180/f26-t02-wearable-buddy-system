# 2026-10-30 照片与资料复核

## 硬件观察

照片中 Wio 与 XIAO 明显错开，无法看到 B2B 插座是否扣合；外观与官方上下重叠装配图不一致。天线线缆本身不提供 MCU 与 LoRa 模块之间的供电/SPI 连接。用户随后明确表示已经断电、重新上下叠合并扣紧，再接回 USB。是否解决问题需用寄存器读回验证，不能只凭照片确认电气接触。

板型外观（带安装孔、按钮的 Wio 扩展板）与 ESP32S3 的 B2B 版本相符。照片中两个板各自的天线插头可见；仅凭照片不能测定接触、电源电压或天线匹配。FPC 天线靠近金属 hub，后续无线测试宜移离金属，但这不能解释 SPI 寄存器读不回。

官方依据：[套装与连接方式](https://wiki.seeedstudio.com/wio_sx1262_with_xiao_esp32s3_kit/)、[官方装配图](https://files.seeedstudio.com/wiki/XIAO_ESP32S3_for_Meshtastic_LoRa/2.png)、[XIAO ESP32S3 文档](https://wiki.seeedstudio.com/xiao_esp32s3_getting_started/)。

## 软件需要修正/保留的事项

- **稳压模式依据不一致：**Wio-SX1262 Module Datasheet V1.1 第 4/6 页明确为 DC-DC 设计。之前另一份 Seeed BSP 使用 LDO，不应把那份例程当成当前模块的唯一依据。1.1.13 候选改为显式 `USE_DCDC`，删除 `regulator-ldo`。
- **TCXO：**datasheet 给出 DIO3 供电、1.7–3.3 V，并要求低于 VCC 至少 200 mV。3.3 V 供电下设置 3.0 V 符合这个范围；诊断试过的 1.8 V 也在范围内。现阶段不能把 TCXO 电压差异当成已证实根因。
- **驱动就绪不是总线验证：**仍必须读回已配置的私有同步字 0x1424，再报告 radio ready。0xffff/0x0000 都不能算通过。
- **早期初始化保护：**保留 deferred radio init，在 main 启动 watchdog 后执行，避免驱动在 main 之前卡死而无法自动回滚。
- **Zephyr 兼容性：**高端口基址覆盖与软件 SPI 空缓冲区补丁均已记录。软件 SPI 的空指针已由崩溃地址定位；高端口覆盖单独没有解决上次问题，不应声称已定位全部根因。
- **后续协议验证：**单板读回通过后，才验证 STATUS/ACK、SOS、QUERY/REPLY、BLE 失联查询。当前实验帧没有认证/加密，不是儿童部署版本；IMU、搭扣、电量仍明确报告未知/不可用。

模块依据：[Wio-SX1262 Module Datasheet V1.1](https://files.seeedstudio.com/products/SenseCAP/Wio_SX1262/Wio-SX1262_Module_Datasheet.pdf)。

旧暂停记录保留为历史；本次用户已明确恢复工作。

## 重新连接后的证据

- 用户重新叠合并扣合 B2B 后，旧版 1.1.4 在升级前就收到 `ACK tag=T01 type=1 seq=4 attempt=1 rssi=-19 snr=13`。
- 1.1.13 候选启动读回 `0x1424`，并在 uptime 20.126 秒自检确认，随后持续收到 ACK。
- 这支持板间连接是前次失败的重要原因。此前仅从 GPIO 驱动源码推断寄存器基址错误，判断过于肯定；旧版在原始 devicetree 下能够通信，故 1.1.14 撤掉该试验覆盖。
- 1.1.14 使用原始 GPIO 定义和硬件 SPI。软件 SPI 补丁只保留为历史诊断材料，不再由构建脚本自动应用；本机 Zephyr 源码已恢复干净状态。
- USB 重新接数据连接后，Mac 识别到两块板：T01 `/dev/cu.usbmodem101`，C01 `/dev/cu.usbmodem1101`。此前照片有一根线似乎接在 PD 口，且系统只识别一块；不能将亮灯当作 USB 数据通信已通。

两端完整 BLE 升级到 1.1.14、自检确认及 SOS/失联/自动查询/恢复/手动查询均已实测。维护模式切换也未出现复位。

另发现真实的 OTA 误报问题：完整更新约 205 秒，原维护宽限仅 120 秒。1.1.15 将维护宽限独立配置为默认 600 秒，正常失联阈值仍为 8 秒；已实测：标签完整 BLE 上传 219.57 秒；辅导员连续采集 296.133 秒无误报，并收到 24 条状态帧。退出维护后的实际失联告警为 9.836 秒，随后 LoRa 查询/回复/ACK 和 BLE 恢复均通过。
