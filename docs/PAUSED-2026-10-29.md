## LoRa 卡点与排查结果

1. 已实现 STATUS / SOS / ACK、重试、QUERY / REPLY 和 BLE 失联触发查询，但没有收到有效的无线 ACK。
2. 原生 SX126x 后端发送超时；LoRaMac-node 后端也未完成发送。
3. 硬件 SPI 读回私有同步字为 `0xffff`，应为 `0x1424`。用户已确认两套都通过 B2B 插座连接。
4. 当前 pinned Zephyr 的 GPIO 高端口驱动/寄存器基址存在可疑不匹配；工程 overlay 加了共享基址覆盖，但**单独这个修改没有解决读回问题**，不能称已找到全部根因。
5. 软件 SPI 对照先暴露了驱动对 NULL dummy TX 缓冲区的空指针访问。已在 Zephyr 本机源码修正一行，并保存为 `patches/zephyr-spi-bitbang-null-buffer.patch`；`scripts/build.py` 会检查后应用，已应用则跳过。没有改动其他 SDK 文件。
6. 修复软件 SPI 空指针后，1.1.10 读回 `0x0000`，仍未通过。SPI/控制信号路径仍未确定，不能断言是硬件损坏或用户接错。
7. 早期软件 SPI 诊断曾卡在 main 之前，因此需要一次 USB reset（仅 read-mac/reset，无 flash 写入）恢复。随后把射频改为 deferred init，在 main 启动 watchdog 后再初始化；1.1.9 的实际崩溃由 watchdog 自动恢复，验证了这项保护。

厂家 BSP 的参考配置为 LDO/3.0 V TCXO；Meshtastic 该板变体使用 1.8 V，模块 datasheet 给出 TCXO 1.7–3.3 V。软件 SPI 诊断使用 1.8 V。后续应根据实际模块确认配置，不要把电压差异直接当作已证实根因。
